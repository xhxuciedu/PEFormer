# Training data reconstruction — summary report

This report consolidates the data-reconstruction work spread across several other
reports into the single narrative requested by the task spec (§AE). Each section links
to the detailed report it summarizes.

## 1. Target dataset definition

Hsu et al. 2026 trained OptiPrime on 297,962 PE experiments: 74,769 newly generated by
the authors (Lib-MMR + Lib-CV screens) plus 223,193 from three prior studies (PRIDICT,
DeepPrime, PRIDICT2.0). Full derivation: `reports/dataset_reconstruction_status.md`.

## 2. Hsu 74,769 reconstruction

Exact. Extracted from `data/raw/hsu2026/41587_2026_3261_MOESM3_ESM.xlsx` (Lib-MMR +
Lib-CV sheets), long-formatted to one row per (design, cell type, PE version). A real
bug was found and fixed during extraction: tandem-duplicated target sequences caused
the protospacer search to match the wrong copy in 28 rows, placing the "edit" up to 30nt
upstream of the nick (biologically impossible) — fixed by taking the leftmost match.
Verified: 100% of rows have a resolved protospacer and NGG PAM; `revcomp(pbs_sequence)`
occurs in the unedited target for 100% of rows (independent orientation check).
Full detail: `reports/hsu_data_validation.md`.

## 3. Exact source composition of the 297,962 experiments

The exact per-partition ground truth (42 partitions: 4 Liu + 20 Schwank + 18 Kim,
labeled with PEmax/epegRNA/MLH1dn/NRCH flags and precise row counts) was recovered from
the paper's own Supplementary Information (page 11 bar chart), transcribed by rendering
the page to a high-DPI image and reading it directly (the PDF's subsetted font defeated
programmatic text extraction). The 42 values sum to exactly 297,962 — effectively a
checksum on the transcription. See `data/manifests/optiprime_context_counts.csv` and
`reports/dataset_reconstruction_status.md`.

OptiPrime's loader code and released model weights independently confirmed the coarser
structure: exactly 12 lab×cell-type groups (Liu×2, Kim×7, Schwank×3), recovered from the
`group_factors` dict in every released fold checkpoint. See
`reports/optiprime_data_loader_reverse_engineering.md`.

## 4. Dataset quality control

- **Duplicate analysis** (`reports/duplicate_analysis.md`): negligible. Of 10,412
  rows initially flagged as "exact duplicate observations," all but 2 share
  `edited == 0.0` by coincidence (DeepPrime's raw efficiency distribution is ~45%
  exact zero, confirmed against the raw source files) — not real duplication. Zero
  cross-study design overlap.
- **Efficiency scale**: verified as fractions in [0,1] for every source (workbook,
  DeepPrime, PRIDICT/PRIDICT2.0); PRIDICT v1's raw background-subtracted `edited`/`indel`
  columns had small negative values (measurement noise, documented and clipped to 0 —
  258 + 6,276 rows respectively).
- **Biological consistency**: sequence alphabets restricted to ACGT (post-cleaning),
  PBS/RTT/protospacer lengths cross-checked against source design fields.

## 5. Historical data (223,193 target) — achieved 187,739 of it

Two parallel reconstruction efforts (ours, and an independently-run `biomni/` agent
given the same task without access to this session's history) converged on the same
residual gap after cross-checking against the exact 42-partition ground truth — see
`reports/biomni_cross_check.md` for the full methodology of that comparison, which
caught and corrected real errors in the first `biomni/` attempt (fabricated groups,
misattributed data) before reusing anything from it.

**Final composition**, `data/processed/optiprime_full_297962.parquet` (262,508 rows,
88.1% of target):

| Source | Partitions matched | Rows |
|---|---:|---:|
| Liu (Hsu, ours) | 4/4 (raw count; see gap below) | 74,769 |
| Kim (DeepPrime) | 18/18 exact | 58,301 |
| Schwank (PRIDICT/PRIDICT2.0) | 18/20 exact | 129,438 |
| **Total** | **36/42 (target-exact)** | **262,508** |

**Remaining discrepancies**, all documented with root-cause investigation rather than
guessed away:

1. **Liu/Hsu: 65,594 target vs. 74,769 available (+9,175 excess).** No coverage/QC
   column exists in the public Supplementary workbook; tested and ruled out: a
   "both PE2 and PE4 present" filter, barcode-collision exclusion, invalid-read
   exclusion (`edited+indel>1`), zero-efficiency exclusion, and OptiPrime's own
   `pe_constants.py` embedding-size bounds. Unresolved after multiple independent
   attempts (see `reports/dataset_reconstruction_status.md` for the full list of
   ruled-out hypotheses). We use the full 74,769.
2. **Schwank K562, PE4+epegRNA (target 21,201): only 823 rows found.** Checked PRIDICT
   v1's full supplementary branch (subscreens, "focused" library zips, Library2),
   PRIDICT2.0's processed data and Excel, and the Ranking_Percentile file. Most likely
   genuinely absent from any public release.
3. **Schwank K562, PE2+epegRNA (target 23,428): +94 excess.** Traced to an unapplied
   PRIDICT2.0 QC exclusion list (`k562_indices_nan.pkl`), not yet resolved to the exact
   count.

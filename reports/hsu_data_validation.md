## 1. How the 74,769 measurements were obtained

The workbook holds two screening libraries, `Supp Table 4 LibMMR` (Lib-MMR) and
`Supp Table 5 LibCV` (Lib-CV). Each sheet has one row per pegRNA design and eight
measurement columns: `{HEK293T,HeLa}_{PE2,PE4}_{editing,indel}`. Melting the four
`*_editing` columns gives one row per (design, experimental context) pair, and the
**only** filter applied is that the editing value is present. No thresholding on
read counts, efficiency, indel rate, edit type or design category is applied.

## 2. Canonical schema and orientation

* `unedited_sequence` / `edited_sequence`: `Designed target (ps-pam-edit)` and its
  edited counterpart, i.e. the protospacer strand 5'->3' with protospacer, then PAM,
  then the edit region. Lib-CV supplies `unedited_target` / `edited_target` in the
  same orientation.
* `protospacer`: located inside `unedited_sequence` by searching for the designed
  spacer, and for the spacer minus a non-genomic 5' G when the full spacer is absent.
* `pam`: the three bases immediately 3' of the protospacer.
* `pbs_sequence` / `rtt_sequence`: pegRNA orientation 5'->3'. Lib-MMR gives the
  extension as `PBS + edit product + homology arm` on the protospacer strand, so
  `pbs_sequence = revcomp(PBS)` and `rtt_sequence = revcomp(edit product + homology arm)`.
  Lib-CV gives `pbs_bind`, `edit_product` and `homology_arm` directly; the same rule
  reproduces its `extension` column exactly.
* `edit_type` / `edit_length` / `edit_position`: derived by stripping the shared
  prefix and suffix of the WT and edited sequences, not by trusting a design label.
* `edit_position_from_nick`: edit start minus the nick position, where the nick lies
  3 nt 5' of the PAM (after protospacer base 17).
* `scaffold_type` and `epegRNA_flag` are left null: the workbook does not record them
  for the library screens, and the spec forbids inventing metadata.

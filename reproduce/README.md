# Reproducing the results in this manuscript

Everything the paper reports is regenerated by one command:

```bash
bash reproduce/run_all.sh
```

No GPU is required and no training happens. The script re-derives every reported number
from the frozen prediction files in `results/`, rebuilds the tables and figures, verifies
the manuscript's prose against the artifacts, and compiles the PDF. Roughly 25 minutes on
one CPU.

## What guarantees the paper's numbers

Three mechanisms, in increasing strength.

**1. Every result table is generated, not transcribed.**
`revision/make_paper_tables.py` reads the analysis JSON and writes
`reports/paper/tables/*.tex`, which the manuscript `\input`s. A number in a table cannot
disagree with the artifact that produced it, because it is not stored twice.

**2. Every prose number is checked against its artifact.**
`reproduce/verify_manuscript.py` holds a registry of 44 numeric claims made in the
manuscript body, each with the artifact and the path into it. It fails if the manuscript
no longer states the artifact's value. This is not decorative: it caught two live
drifts while the revision was being written — a headroom gap quoted from a superseded
script, and a development-fold mean from a different random seed.

**3. Every analysis script records its own provenance.**
Each task script writes the git commit, the seed, and a SHA-256 prefix of every input
file into its JSON output, and takes `--seed`. `revision/_common.py` implements this
once so the eight task scripts cannot record it differently.

## Retraining from scratch

Not part of `run_all.sh`, because it is roughly 60 GPU-hours and the frozen checkpoints
are what the paper reports. The recipe is one command per model per fold:

```bash
PYTHONPATH=src .venv/bin/python scripts/train/train_pilot.py \
  --config configs/round5/baseline_ordinal_ssm.yaml \
  --sequence-mixer ssm --ordinal-head --run-name <name> --val-fold <k>
```

`--val-fold k` reproduces official fold *k*; `--dev-folds-file
data/processed/round3_dev_assignments.parquet --dev-fold-col round3_dev_fold_<i>`
reproduces development fold *i*. Every run writes `results/runs/<id>/run_info.json`
carrying the git commit, dataset SHA-256, seed, fold, parameter count, optimiser
settings, precision, selected epoch, GPU model and runtime.

Mechanisms are behind flags, each with its matched control:

| flag | mechanism | control |
|---|---|---|
| `--sequence-mixer {attention,ssm,selective,selective_frozen,hybrid_alt,hybrid_par}` | sequence mixer | `selective_frozen` for `selective` |
| `--ordinal-head` / `--simplex-head` | outcome head | the other head |
| `--context-lowrank R` | context-conditioned non-diagonal map | `--context-lowrank-control` |
| `--censor-limit D` | censoring-aware ordinal loss | `--censor-shuffle-control` |
| `--row-weights` | the comparator's own per-row loss weights | an unmodified run |
| `--n-cross-blocks N` | cross-attention capacity | a parameter-matched depth change |

## Held-out discipline

The 20,509-row held-out set is gated. `src/pe_rankformer/evaluation/heldout_guard.py`
aborts unless `--allow-heldout-evaluation` is passed, and appends every access to
`logs/heldout_evaluations.log`. That log is the audit trail behind the four-access
accounting the manuscript reports. Nothing in `run_all.sh` evaluates on held-out rows;
it reads the frozen prediction vectors produced by those gated accesses.

## Data

The corpus is not redistributed here. `data/optiprime_train_mix/` holds the 58 CSVs
supplied by the comparator's authors and is deliberately excluded from version control —
publishing it is their decision, not ours. `scripts/data/build_optiprime_official.py`
rebuilds `data/processed/optiprime_official_318471.parquet` from those files and asserts
the 297,962-row training count. Without the CSVs, steps 2–7 still run from the frozen
predictions in `results/`, which are committed.
